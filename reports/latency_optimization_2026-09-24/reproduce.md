# Reproducing this experiment

Run commands from the original repository, `/Users/julien/Documents/Repos/SelfJev`, on `master`, with `PYTHONPATH=src`. The trained R1 checkpoint must exist at `runs/tree_4b/adapter`; its SHA-256 must match `manifest.json`. Model weights and adapters are local artifacts, not included by Git's normal `runs/` ignore rule.

## Environments

The HF environment is installed from `uv.lock`. The separate vLLM environment uses vLLM 0.30.0 because it pins a different Torch release. Exact installed packages are recorded in `environment_hf.txt` and `environment_vllm.txt`; GPU/driver details are in `nvidia_a10g.txt`.

Do not run training and latency benchmarks concurrently on the same GPU. Load/compile time is outside the resident-model timing results. These are local server-side measurements; HTTP/network time is excluded.

## Runtime comparison

`scripts/run_tree_latency_phase1.sh` runs the HF reference, direct-mask parity, benchmarks, and merged/unmerged development evaluations. The immutable pre-change mask implementation is under `baseline_source/`.

Merge the R1 adapter for vLLM:

```bash
PYTHONPATH=src .venv/bin/python -m personal_jev.vllm_tree merge \
  --adapter runs/tree_4b/adapter --out runs/tree_4b/merged
PYTHONPATH=src /home/ubuntu/vllm-env/bin/python scripts/bench_tree_vllm.py \
  --out reports/latency_optimization_2026-09-24/vllm_a10g.json
```

The original vLLM run contains cold-prefix and repeated-identical-request timings. `--document-warm` adds a third mode: clear cache, prefill only document-root tokens, then measure a full request whose questions/candidates have not been cached. `--skip-quality` is only for extending an already evaluated backend's timings. Never use repeated-identical-request numbers as new-question latency.

## Compact adaptation

The challenge file was frozen before training; do not regenerate it when reproducing the recorded comparison. `configs/tree_4b_compact_v2.json` fixes data selection, initialization, format, teacher weight, training schedule, and validation checkpoint selection.

```bash
PYTHONPATH=src .venv/bin/python scripts/tree_latency_experiment.py teacher \
  --config configs/tree_4b_compact_v2.json \
  --out reports/latency_optimization_2026-09-24/teacher_train.json
PYTHONPATH=src .venv/bin/python -c \
  'from personal_jev.train_tree import train; train("configs/tree_4b_compact_v2.json")'
bash scripts/evaluate_tree_compact_phase2.sh
```

The evaluation script refuses to start without completed training metadata. Its optional trainer PID argument waits for that process to finish first. It evaluates the validation-selected adapter on the established development benchmark and frozen challenge, checks GPU mask parity, and measures HF and vLLM latency. The script's vLLM environment path is specific to the recorded AWS setup; change that path when reproducing elsewhere.

`tree_format.json` travels with every compact adapter and merged checkpoint. Loading it automatically selects the correct format; conflicting explicit formats or changed format hashes raise an error. R1 remains the default when no format sidecar exists.

## Analysis

```bash
PYTHONPATH=src .venv/bin/python scripts/compare_compact_quality.py \
  reports/latency_optimization_2026-09-24/r1_merged_development.json \
  reports/latency_optimization_2026-09-24/compact_development.json \
  --out reports/latency_optimization_2026-09-24/compact_development_comparison.json
.venv/bin/python scripts/summarize_tree_latency.py
```

Quality comparisons pair question IDs, require aligned targets/candidates, and bootstrap whole source records. Family intervals are descriptive; they are not corrected for multiple comparisons. All predictions and all timed repetitions remain in the raw JSON reports.

The optional static figure is generated by `scripts/plot_tree_latency.py` with Matplotlib 3.10.0. It reads measured JSON files; the plotting dependency is separate from the inference environments.
