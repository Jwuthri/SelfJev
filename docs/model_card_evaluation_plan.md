# Model-card evidence and the next comparison

The visual card is generated by `scripts/docs/build_model_card.py`, with prose in
`scripts/docs/model_card.template.md`. Output: `weights/selfjev_4b/README.md`, `assets/` and `reproduce/`.
It uses saved reports and `data/all.jsonl.gz`; no model runs are needed to rebuild it.

## Available now

- All 11 public-source slices, 300 questions each, drawn from the existing development benchmark. Adaptations
  include smaller candidate sets, binary MNLI and exact-set GoEmotions. Do not describe these as official
  full-dataset leaderboard results.
- The two authored suites: text decisions and AI response review, using current TreeServer reports.
- Seven systems with 0.6B, 4B and 8B nominal backbones, on the same public-source questions. This includes stock
  rerankers and different fine-tuning recipes; it is not a controlled scaling experiment.
- Eikos-4B on the authored text-decision suite, and selected historical architecture/training checkpoints.
- Source hashes, CSV/JSON chart data, PNG/SVG figures and the generator distributed with the card.

## Independent benchmark stage (not run)

[Lev's card](https://huggingface.co/interfaze-ai/lev) provides the design reference and points to a S1Bench harness.
The missing comparison is a common external benchmark, not another chart over incompatible scores.

1. Resolve and pin the exact S1Bench harness commit, dataset revisions and item manifests before inference.
   Lev currently reports 13 subsets and 3,880 scored items; confirm those against the manifests, rather than
   treating the card text as the authoritative manifest. Keep a full-suite score separate from any leaderboard
   score over a smaller shared subset.
2. Register the frozen evaluation batch in the canonical data catalog, preserving source dataset, item ID,
   original question, option order, scoring rule and split. Audit exact/near document overlap with our training
   corpus. Record overlap exclusions and full-set results separately. Do not train or fit calibration on these items.
3. Freeze SelfJev's adapter hash, base revision, engine, option transform and decision rule. Use each competitor's
   documented inference recipe, with pinned checkpoint and code revisions. Identify unsupported question types
   and count failures; never silently drop them from an average.
4. Evaluate SelfJev, the untuned backbone and at least two relevant open decision models (starting with Lev).
   Add larger models only when the same harness and data are available. Previously published scores may be cited
   separately, but belong in a combined plot only after verifying identical item coverage and metric definitions.
5. Report per-subset results, macro average, completion rate, appropriate constant baselines, and paired
   uncertainty estimates clustered by shared document. For graded outputs include an ordinal metric in addition
   to exact accuracy. Keep calibration measures separate from accuracy.
6. Plot accuracy versus total backbone size on this one external suite. For mixture-of-experts models disclose
   both total and active parameter counts; do not mix them on one unlabeled axis. Leave undisclosed API sizes off
   the parameter axis.
7. Measure latency on the same GPU with fixed workloads: document lengths, questions, options, concurrency,
   warmup and repetitions. Separate engine compute, full HTTP latency, peak VRAM and cold start. Historical
   H100 timings of our archived models cannot be relabeled as current SelfJev timings.

New model inference must run on AWS under the repository rules. Quote a concrete run budget and obtain the
required approval before allocating resources. The earlier merged-checkpoint budget does not cover this benchmark campaign.

## Publishing

or the historical manifest. Verify public bytes at the resulting Hub commit. Local source changes require a
separate user-requested git commit before the generator is available from the GitHub default branch.
