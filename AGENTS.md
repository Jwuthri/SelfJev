# Read this first (Claude Code, Codex, any agent session)

Several AI sessions work on this repo at the same time. To avoid redoing work or colliding:

1. **Before starting**, read two files:
   - [docs/experiments.md](docs/experiments.md), the current state: every test result (a table generated by
     `uv run python scripts/ledger.py`; never hand-edit its numbers), conclusions, dead ends not to redo, known issues,
     and open ideas you claim before starting.
   - [docs/JOURNAL.md](docs/JOURNAL.md): *In flight* (who runs what, on which box, until when) and a dated log.

   Add your job to *In flight*, and claim your idea in experiments.md.
2. **When you finish** anything (experiment, analysis, fix, failure, dead end):
   - add a dated entry at the top of the JOURNAL log: what, why, data/config, numbers with report paths, cost, verdict;
   - update experiments.md (conclusions, dead ends, idea status);
   - re-run `scripts/ledger.py` if you wrote a test report, and `scripts/eval2_summary.py` if you scored eval2;
   - if a headline result changed, update the docs site pages too: [docs/findings.md](docs/findings.md) and
     [docs/leaderboard.md](docs/leaderboard.md) (the generated tables are embedded, the prose is not).

   Numbers come from report files, never from memory.
3. The formatted state of the project is the docs site built from `docs/` ([docs/index.md](docs/index.md)): key
   findings, leaderboard, speed, models, data, open questions. Topic write-ups: [docs/tree_model.md](docs/tree_model.md)
   (the architecture of every best model), [docs/hardcases_round2.md](docs/hardcases_round2.md) (round-2 data),
   [reports/latency/summary.md](reports/latency/summary.md) (Jev vs ours), and the reviews in `reports/*_2026-09-2*/`.
4. The system itself: [README.md](README.md). Best model: `tree_4b_instruct_r2x64` ([docs/leaderboard.md](docs/leaderboard.md)).

## Hard rules

- Never train on, or fit prompts, thresholds or temperatures on, **test** labels. The test split (`hf.jsonl` + `eval.jsonl`
  test, 3,471 questions) has been reused for many development decisions: call it a development benchmark when reporting.
  Label any change motivated by a test-set diagnosis as such.
- LLM labels are not ground truth. Training labels come from authored targets checked by the blind GPT-6 Astra judge
  (`scripts/build_hardcases.py`); Jev answers never decide a training label.
- **Never run evals, training or other heavy model jobs on the user's laptop** (MPS included). Use an AWS GPU
  instance; only tiny unit tests run locally.
- **Paid resources** (AWS, OpenRouter, OpenAI) need the user's explicit OK with a price, every time.
  - AWS: tag instances `Project=personal-jev` and `Name=<your job>`; add a `shutdown -h` cap with terminate-on-shutdown;
    terminate and delete the SG and key pair when done; log the cost.
  - Never stop, terminate or modify another session's boxes, or anything production (`eks-prod-*`). A tagged
    `Project=personal-jev` box listed in JOURNAL *In flight* belongs to its owner. If one looks orphaned, ask its owner
    or the user first. On 2026-09-24 an unlogged `stop-instances` killed a 10-hour training run halfway.
- API keys live in `~/.zshrc` (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`). Use them via `zsh -ic '…'` and never print them.
- Work directly in the original checkout on its existing `master` branch. Do not create branches or worktrees unless the user explicitly requests them.
- No git commits unless the user asks. Re-read a shared file right before editing it: other sessions edit the same files.
- The user's shell is zsh: `$VAR` holding several flags doesn't word-split, and `echo ===` fails (`=` expansion).
  Put multi-step commands in bash scripts.

## Commands

```bash
uv sync && uv run pytest -q          # tests (tests/test_model.py downloads the 0.6B model)
uv run python scripts/ledger.py      # refresh the results table in docs/experiments.md
uv run --no-project --with zensical==0.0.65 python -m zensical serve   # preview the docs site (deployed from master)
uv run pjev --help                   # classify / eval / calibrate / compare / bench / serve / train / train-tree ...
```
